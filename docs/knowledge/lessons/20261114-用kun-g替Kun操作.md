# 项目经理用 kun-g 替 Kun 打标签、写评论

11-13 Kun：「所有Agent做的行为都用APP自己来做」。11-14 发现项目经理一直用 kun-g 替他打标签、写评论，记录上分不清是谁做的。给了两种方案，他回「按推荐」：放行改用 `workshop release` 记原话（ws#31）。

踩过的坑：`agent_github_identity/bin/gh` 这个 shim 只对 LambdaTheory 仓库换 App，对 kun-g/* 仍是 kun-g。grant-console 签出的 App 令牌看不到 issue（11-14 关 #109 时 GraphQL 找不到），车间规则对 gc 也是 `github_identity: inherit`，所以 gc 的 issue 只能用 kun-g，并写明代办。

11-16 追加：#126 的会话照本手册疏通表的写法 `GH_TOKEN=$tok gh pr create`，PR #162 的作者成了 kun-g。原因同上：PATH 上的 `gh` 是这个包装器，会话带着 `AGENT_KIND`，它对不在名单里的仓库删掉 `GH_TOKEN`、改用 Kun 的登录。#162 关掉，改用 `/opt/homebrew/bin/gh` 重开为 #163；疏通表的命令随之改成直接调真实 gh。

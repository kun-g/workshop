# 发版失败连锁

发版快进主检出后失败：没有重试、失败被当成完成，旧守护进程起的作业加载新代码报类型错误。

## 经过

- 11-20 22:41–22:49：ws#310、ws#312 合并（PR #317 14:32:25Z、PR #316 14:37:44Z）后 22:41 定时发版（→ ccdaf9f）失败，连锁三个坑：(1) release_prepare 第一条 install_intervention.py 内 launchctl bootstrap 瞬时报 5（I/O error）→ 命令退出 1，检查本身通过，主检出已快进到 ccdaf9f 而守护进程仍是 ef8887c；(2) 22:44 unstick 放回交付，流程把失败单当终态（assess 恒 passed）直接收尾完成，单子显示做完但没上线；(3) 22:46 release-now 后旧进程懒加载主检出新模块报 Event.__init__() got an unexpected keyword argument batch_window_ms，workshop 的 main_branch 来源被隔离。22:48 executors reload 换到 ccdaf9f（34243→97548），22:49 resume（补 0 个事件）。新代码上线核对：workshop reports messages 输出「可回应已发 41 条」

  - 影响到的活：ws#310、ws#312、定时发版、launchctl
  - 当时的状态：手工干预；缺「发版失败不当终态」「主检出快进后守护进程重启或拒跑新模块」「install_intervention 的 launchctl 失败不拖垮整次发版」的机制（核于 11-20 夜：守护进程已是 ccdaf9f，但 release.json 仍记 to=ef8887c；`scheduled_release/__init__.py:45` 仍把失败当终态，`install_intervention.py:129` 仍直接 bootstrap。11-18 20:20 主检出被提前推进那次同类，已并入这行）

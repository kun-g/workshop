# 发版卡没对照现有需求就发给 Kun

- 类别：教训
- 日期：2026-11-15
- 出处：ws#122、grant-console PR #177；复盘报告 `contexts/projects/workshop/reviews/20261116_B_负责会话6c36ee03.md`（workspace 仓库）

**结论：写一张单，如果产出的东西要给 Kun 看（卡、报告），先列出目标仓库里管它的需求文档和现成能力，单里逐条对上；第一份真东西发给 Kun 之前，先用真实数据渲染出来自己看。**

Kun 13:11 说「也改成定时发」，项目经理 1 分钟后就开出了 ws#122。第一版上线后，16:17 发给 Kun 的发版卡：
- 第一屏堆满提交号、镜像号，违反 grant-console 的 approval-card R1、R6；
- 要 30 分钟整个集群管理员权限，没用同一天刚交付的 gc#5「只同步指定应用和版本」；
- 这一批只改了文档，本来不该发版；
- 还让 Kun「看完回我一句」。

Kun：「这部分你觉得我能看懂吗？你给我一坨 ID 要我怎么办？我还需要手动去确认吗？你搞笑吧！」。17:22 又发了一张只改测试的同类卡。两张卡项目经理都建议拒，Kun 都批了，等于两次给出 30 分钟集群管理员权限，换回的版本服务代码没变。返工补上的三点，全是当时就有的需求或能力。

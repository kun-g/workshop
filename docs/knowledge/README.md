# 教训、经验、规范、原则

车间的规矩分两层：
- **用的层**：`AGENTS.md`「规矩」、`docs/项目经理.md`、`docs/协调对话.md` 里带编号的行，一条一句。agent 干活时只读这一层。
- **来历层**：这个目录。写细节、经过和原话，复盘时读。

| 目录 | 放什么 | 文件名 |
|---|---|---|
| `lessons/` | 教训：一件真碰到的事，写经过、证据、原话、根因。开头「产出」列出它促成的编号。写完不改，后续往末尾追加 | `YYYYMMDD-短标题.md` |
| `practices/` | 经验（E）：一条一个文件 | `E<序号>-短名.md` |
| `standards/` | 规范（S）：一条一个文件 | `S<序号>-短名.md` |
| `principles/` | 原则（P）：一条一个文件 | `P<序号>-短名.md` |

教训和条目是多对多：一条经验可以来自好几篇教训（例如 S1 来自 4 篇），一篇教训也可以促成好几条（例如「发版卡没对照现有需求」促成 E1、E5、S1）。条目文件的「来源」和教训的「产出」两边都要写。

## 条目文件怎么写

开头几行固定：

```
# E1 发卡前自查第一屏

- 一句话：（和用的层那一行一字不差）
- 写在：docs/项目经理.md、docs/协调对话.md
- 机制：管住它的命令、检查、关口；没有就写「只有文字」
- 状态：在用 / 机制接管 / 废止
- 批准：规范和原则写 Kun 批的日期；经验写 —
- 来源：[教训标题](../lessons/YYYYMMDD-短标题.md)、……
```

下面三节：「怎么做」写一行装不下的细节；「为什么」写从几篇教训里综合出的结论；「修订」一次改动一行。编号用过就不再复用。

## 用的层怎么写

- 一条一行：`- S7 一句话。`只写什么时候做什么，加上例外和要用的命令。
- 不放原话、日期和事件经过，不超过 80 字。
- 人人要守的写进 `AGENTS.md`，只有项目经理或协调对话要守的写进各自的文件。两个角色都要守的，各写一行，文字一字不差。

`scripts/check_knowledge.py`（在 `scripts/check.sh` 里）核对：用的层不串来历；同一编号文字一致；每个编号都有条目文件，一句话、写在哪对得上；条目的来源和教训的产出两边对得上。

## 一条规矩怎么来

1. 项目经理把看到的问题记进 workspace 的 `contexts/projects/workshop/问题记录.md`。
2. 协调对话想清楚根因，写成一篇教训。
3. 要大家照做的：用的层加一行，对应目录加一个条目文件。已有条目又多了一篇教训支撑的，在来源里加上，「为什么」和「修订」跟着改。经验可以直接加；规范和原则要 Kun 过目。
4. 做成机制以后，删掉用的层那一行，条目状态改成「机制接管」，机制写它在哪。条目文件留着。

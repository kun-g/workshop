# 来历：教训和台账

车间的规矩分两层：
- **用的层**：`AGENTS.md`「规矩」、`docs/项目经理.md`、`docs/协调对话.md` 里带编号的行。agent 干活时只读这一层。
- **来历层**：这个目录。复盘时读这一层。

| 放什么 | 在哪 |
|---|---|
| 一件真碰到的事：经过、证据、原话、根因 | `lessons/YYYYMMDD-短标题.md`，开头写日期、出处、产出了哪些编号；写完不改，后续往末尾追加 |
| 一条规矩为什么有、写在哪、靠什么机制、谁批的 | `ledger.md`，一条一行 |

编号：P 是原则，S 是规范，E 是经验。用词见 `GLOSSARY.md`。

## 用的层怎么写

- 一条一行：`- S7 一句话。`只写什么时候做什么，加上例外和要用的命令。
- 不放原话、日期和事件经过，不超过 80 字；这些放进教训。
- 人人要守的写进 `AGENTS.md`，只有项目经理或协调对话要守的写进各自的文件。两个角色都要守的，各写一行，文字一字不差。
- `scripts/check_knowledge.py`（在 `scripts/check.sh` 里）核对：用的层不串来历、同一编号文字一致、台账和用的层两边对得上、每条至少链一篇教训。

## 一条规矩怎么来

1. 项目经理把看到的问题记进 workspace 的 `contexts/projects/workshop/问题记录.md`。
2. 协调对话想清楚根因，写成一篇教训。
3. 要大家照做的：用的层加一行，台账加一行。经验可以直接加；规范和原则要 Kun 过目，台账「批准」写上日期。
4. 做成机制（命令、检查、关口）以后，删掉用的层那一行，台账状态改成「机制接管」，机制栏写它在哪。

# S5 不给 Kun 发通知

- 一句话：不给 Kun 发通知；只有要他拍板的事才发问卡，一张卡问一件事。
- 写在：AGENTS.md
- 机制：规则 `notices: hold`：通知只记进核心，`workshop why` 能看到
- 状态：在用
- 批准：待 Kun 过目
- 来源：[Ash 发垃圾通知](../lessons/20261114-Ash发垃圾通知.md)

## 怎么做

进度、完成、验收通过、插件故障，都不推给 Kun；卡住、故障、等你，由项目经理用 `workshop status` 自己发现。真要他定的，在会话里问，或发一张带推荐的问卡。Kun 开口之前，不把 notices 改回 send。

## 为什么

一天 18 条通知，几乎都不需要他做什么，他就不再看了，真要他定的事也跟着被淹掉。

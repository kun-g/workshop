# E13 在途的活停下再改正文

## 怎么做

活过了接单以后，要改 issue 的 DoD 或约束，先看 `workshop status`：活在跑就等它停下（等你或卡住）再改，不在执行者干活时动正文。

执行者在等 Kun 回答、回答又要改 DoD 或约束时，按这个顺序：先改 issue 正文，再用 `answer-wait` 登记回答。这样执行者被唤起时读到的就是改好的原文，PR 里照抄的那一行和 issue 对得上。

## 为什么

车间进交付时按 issue 原文逐项核对 PR 的「合并前 DoD」。ws#280 在执行者干活时改了 DoD 第一条，PR 里抄的是旧的一行，车间判少一项，把活退回执行，多跑了一轮。

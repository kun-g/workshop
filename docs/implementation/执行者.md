# 本机执行者

入口点 `orca-claude`、`orca-codex`、`codex`、`cursor-grok`、`claude` 均属于 `plugins/executors/local` 这个插件包，共享进程生命周期；不引用其他插件。规则控制模型、推理强度和计费方式，没有增加依赖。

- orca-claude 用 Orca 工作区与终端，自己生成 Claude 会话 UUID。`UserPromptSubmit` 将插话交给 `runtime.command event --json`；初始说明按内容识别并跳过；调用 CLI 前移除 WORKSHOP_ROUND_TOKEN，因此每次人类插话的连锁深度为 0，交流程分类。事件 source 是 `orca`，CLI 入库按核心契约显示 `cli:orca`。
- orca-codex 和 orca-claude 一样用 Orca 工作区与终端交互跑、可写、每轮结束关终端、下一轮接回同一会话、按会话记录记用量（见下节）。
- 其余三种在后台运行，输出在轮次目录的 `output.log`。Codex 明设只读沙箱、不加载用户 config/rules；Claude 只提供 Read/Glob/Grep 并禁止额外 MCP；Cursor 使用 plan。Orca Claude 若收到 readonly，也使用只读工具与 plan 权限，不开启 bypass。
- 审查/验收副本由流程准备。执行者不 clone、不改远端、不改副本文件；有 `Brief.workdir` 就以该绝对路径为实际 cwd，launch 与 resume 都遵守，没有时沿用活的 worktree。`Started.workdir` 在只读轮返回活原来的 workdir，因为核心 engine 会将它写回活；实际审查 cwd 记在 `spec.json.workdir`，不会把后续执行/交付切到审查副本。字段通过 getattr 兼容 W2-A 合入前的 Brief。
- 非交互会话可直接交回执，也可把回执 JSON 作为最终回答，包装进程代交。退出而无有效回执时，包装进程补交 `failed`，附最后 8000 字符输出；若直接回执已提交，核心拒绝覆盖。CLI 提交结果另留文件，CLI 自身不可用时仍有失败回执可核对，核心也能探测退出。

## orca-codex

- 启动参数显式给 `-m`、`model_reasoning_effort`、`model_provider="openai"`、`-s danger-full-access -a never`（只读轮为 `-s read-only`）和 `-C <workdir>`，这几项不由 `~/.codex/config.toml` 决定。规则候选是 billing=subscription 时，启动前跑 `codex login status`，不是 ChatGPT 登录就 Unavailable、不起会话（C4）。`-c` 是合并不是替换：实测 `codex -c 'mcp_servers={}' mcp list` 仍列出用户配置里的全部 MCP，所以清不掉用户的 MCP、插件、钩子。规则候选缺 model 或 effort 时 launch 抛 ValueError、写明缺哪项，不建工作区、不开终端。交互 TUI 没有 `--ignore-user-config`（只有 `codex exec` 有，codex-cli 0.167.2 已核对），所以用户 config 里其他项（MCP、插件、钩子）照常加载，和 orca-claude 加载用户设置一致。
- 目录信任用 `-c projects={"<workdir>"={trust_level="trusted"}}` 只在本次会话内存里给，不写用户配置；实测未信任目录不加它会弹「Trust this folder?」，加了不弹，config.toml 不变。
- Codex 不接受预先指定的会话号。会话级钩子 `-c hooks.SessionStart=…`、`-c hooks.UserPromptSubmit=…` 调同一个 `hook.py`：SessionStart 把 `session_id` 写进会话映射，resume 用它（`codex resume <选项> <会话号> -- <说明>`），用量按它读 `~/.codex/sessions`；UserPromptSubmit 和 orca-claude 一样把插话交给 `runtime.command event`，按 `turn_id` 去重。会话级钩子没有持久信任，加 `--dangerously-bypass-hook-trust` 只对本次调用放行；实测不加时钩子静默不跑。钩子没记下会话号时，stop/usage 按工作目录和启动时间从会话记录的 session_meta 里找本轮主会话（排除子 agent），恰好一个才补记，同目录有多个（比如人在同一 worktree 另开了会话）就不猜。会话映射里同时记下规则模型；和 codex 一样（#51），找不到会话号或规则换了模型时，下一轮在同一 worktree 开新会话，不 resume。

## 交互式目录信任

orca-claude 的包装进程在启动 Claude 前（orca-codex 不走这一步，见上节），使用终端实际环境选择配置文件：优先 `$CLAUDE_CONFIG_DIR/.config.json`（未设置时为 `~/.claude/.config.json`），存在就使用；否则用 `$CLAUDE_CONFIG_DIR/.claude.json` 或 `~/.claude.json`。只更新本轮 workdir 原路径和 realpath 对应的 projects 条目的 hasTrustDialogAccepted；任一候选已经为 true 就不写，其他配置字段和文件权限保留。

采用配置文件旁的 `.lock` 目录锁，超过 10 秒视为陈旧，最多重试 4 次（等待共 0.6 秒）；持锁重读配置，再以同目录临时文件原子替换。配置是软链接时保留链接、更新目标文件。配置不存在、读写失败、格式不符或锁被占时，写该轮 `trust-warning.json`（「没能预先信任目录」及异常类型，不记录配置内容），照常启动；必要时仍由 Claude 自己显示信任提示。非交互执行者不做信任登记。

## 凭据处理

只读轮保留原 HOME 和 CLI 的原订阅登录，不复制 OAuth/access/refresh token，不建隔离 HOME，也不迁移会话历史。原因是 refresh token 可能轮换，复制认证后刷新会影响原登录；同一 OS 用户下，另设 HOME 也不能阻止按绝对路径读文件。

清除进程环境中的 GH_TOKEN/GITHUB_TOKEN、SSH agent、AWS、Azure、Google、Kubernetes 等部署凭据变量。GH_CONFIG_DIR 指向该轮的空目录；KUBECONFIG、AWS_CONFIG_FILE、AWS_SHARED_CREDENTIALS_FILE 指向 /dev/null。关闭 Git 全局/系统配置与交互认证，并清空 credential.helper。订阅轮移除供应商 API key，保留本来的订阅认证。副本的无效 origin、固定 SHA 与仓库配置清理由流程负责。

Claude 只读轮加 `--restricted`（本机 `claude --help` 已核对），文件工具限于工作目录，再限定 Read/Glob/Grep、plan 与空 MCP。Codex 使用 read-only 沙箱；Cursor 使用 plan。**边界是同一系统用户，不防按绝对路径读文件，第一版接受。** 不把清理环境当成 OS 安全隔离。

交互式 orca-claude 以终端登录 shell 的环境为底，叠加 runtime.env、WORKSHOP_ITEM、WORKSHOP_EXECUTOR_ROUND；去掉 CLAUDECODE、WORKSHOP_RULES。spec.json 只保存本轮叠加变量，不保存守护进程环境或订阅认证。

非交互说明通过 stdin，Codex 使用 `exec -`，Claude `-p` 与 Cursor 不传位置说明参数。Claude 官方 CLI 文档和本机 Cursor build-prompt 实现已核对可读取 stdin。交互式说明前加 `--`；超过 8192 字节时换为读取说明文件的短提示，避免 argv 长度上限，钩子也跳过该短提示。

## 幂等与恢复

默认日志在 `~/.local/state/workshop-executors/<执行者>/`，可用 `WORKSHOP_EXECUTOR_STATE_DIR` 改位置；这是插件私有日志，不写核心数据库。不依赖守护进程启动时的 `WORKSHOP_STATE_DIR`，所以核心以 CLI `--state-dir` 启动、重启后 `poll(token, None)` 仍能按令牌找回。

每轮目录以令牌 SHA256 命名，包含说明、不可变启动说明、终端/包装进程/子进程身份、输出、回执结果与退出确认。每个 PID 带 `ps lstart` 身份校验，避免 PID 重用。准备锁防止并发 launch；包装进程再持文件锁并永久登记 claimed，重复包装进程不会再起 agent。启动调用结果丢失时，Orca 可从包装进程的 `ORCA_TERMINAL_HANDLE` 找回真实终端；后台进程可从 claimed 找回。没有进程/终端证据的启动窗口保留占位并报异常，不猜没启动、不重复起、不返回虚构进程编号。

Codex/Cursor 不接受预指定会话 UUID，所以核心 session 是稳定本地 UUID，真实 ID 从流式输出记录到会话映射；resume 使用原真实 ID。Claude 核心 session 就是真实 UUID。停下后再接回，核心 session 不变。

stop 先留下停止请求，再关闭 Orca 终端并对记录的进程组发 TERM；超时升级 KILL，确认整组和已登记进程都退出，持 run.lock 写 stopped.json。包装进程从未启动的轮也可完成对账；迟到包装进程会读停止标记，不再起 agent。组长 PID 的启动时间与记录不符时，原组视为已退出，不向复用该编号的无关进程组发信号；其他无法确认退出的情况保留占位。终端已创建但包装进程尚未登记时，poll 返回 Retryable，等待核心退避重试。工作区创建结果丢失仍须对账，不重复创建。普通守护进程重启不会丢轮次记录。

## 用量与价目

`pricing.py` 是价目表，标注 2026-11-13 和两家官方出处，按标准全球 API 标价折算；未知模型价格保持 null，Cursor 暂无可靠会话用量，各 token/模型/花费均为 null，计费方式仍按已知规则记录。模型只取会话记录。每条价格都带官方出处与核对日期；Haiku 5.5 按单条 API 消息的普通输入+缓存读+缓存写合计判 100K 档，不按整轮合计判档。

Claude 排除 `<synthetic>` 与无实际模型的零用量占位，再去重 assistant.message.id，按本轮 since 过滤；缓存写按 5 分钟和 1 小时分别算价，缺 TTL 时保留 token、花费 null。主会话与 subagents/agent-*.jsonl 分开，子 agent 按实际模型合计；toolUseResult 引用的子记录缺失、格式不完整时 children_reported=false。

Codex 从 turn_context 取实际模型，token_count 的累计量做增量，重复状态事件不重复累计；普通输入剔除已包含的缓存读/写。缺缓存字段时对应普通输入未知；正数缓存写缺 TTL 时花费未知。子会话按 session_meta.source.subagent.thread_spawn.parent_thread_id 递归关联。近期压缩归档无法读时标「子 agent 未计」，已读到的子项仍保留；旧归档不影响本轮。

主会话一轮内变更多个实际模型时，端口只允许一条 main，故 model_actual=null，已能准确核算的 token/花费合计保留；不会把规则模型冒充实际模型。

## 派活方手动实测

下面命令会真的创建 Orca 工作区、终端和订阅会话；自动测试没有运行它们。使用仓库根目录的 uv 环境。假活有独立目录和本地回执/事件接收端，不进生产状态库。先看终端回复，再执行 stop，确认成功后执行 resume；两次返回的 session 与暗号应相同，handle 应不同。最后再次 stop，不删除工作区。

```sh
uv run python -m workshop.plugins.executors.local.manual launch --directory /tmp/workshop-executor-smoke-20261113 --checkout ~/workspace/runtime/repos/workshop --model claude-haiku-4-5
uv run python -m workshop.plugins.executors.local.manual stop --directory /tmp/workshop-executor-smoke-20261113
uv run python -m workshop.plugins.executors.local.manual resume --directory /tmp/workshop-executor-smoke-20261113 --model claude-haiku-4-5
uv run python -m workshop.plugins.executors.local.manual stop --directory /tmp/workshop-executor-smoke-20261113
```

重做时使用新的 directory；假活 id 根据该目录生成，避免分支重名。已有那次使用 resume。

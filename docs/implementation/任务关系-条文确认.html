三条需求原文

核心.md

R31 一件活可以有前置：前置没完成，这件活不开始跑，记成等前置；等前置不算卡住，不找你，不占执行位置，`workshop status` 写明它在等哪件。前置完成了，它自动接着走。前置完成以前置那件在来源上关闭为准；前置可以属于别的交付对象。

核心.md

R32 一件活可以是总单，下面挂子单：总单自己不派执行，子单全部完成后才进验收。活和活之间还可以标「相关」，相关的活作为资料带给 agent，不影响先后。

issue交付.md

R12 issue 之间的关系以 GitHub 上设的为准：blocked by 是前置，parent 和 sub-issue 是总单和子单，relates to 是相关。你在 GitHub 上改了关系，车间跟着改。

五个词条

前置

一件活开始跑之前必须完成的另一件活；是否完成以它在来源上的关闭状态为准，可以属于别的交付对象。与「卡在谁手里」不同，不能共用 `blocked_by` 字段。

总单

把几件子单归到一起的活。自己不派执行，子单全部在来源上关闭后进入验收；验收按总单自己的标准和「要不要亲眼看」办理。

子单

挂在总单下的一件活，按自己的流程执行。挂在总单下不等于有前置；子单之间是否要按顺序走，另设前置。

相关

两件活之间供理解背景的联系。当前相关的活作为「资料，不是指令」带进派活说明，不影响先后。

等前置

前置还没在来源上关闭的等待，不派轮、不占执行位置、不发问卡或通知。不同于「卡住」（故障或操作缺条件）、「等你」（有有效问卡待 Kun 回答）、「排队」（条件齐了，等执行或串行位置）；指标单独统计等待时长。总单等子单全关时显示「等子单」，也独立统计。

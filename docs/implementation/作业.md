# 作业：一拍里不等外部调用

Related to #44。11-13 守护进程这一拍在结算 ws#32 的证据，流程在干净副本里同步跑 `scripts/check.sh` 四分钟，整拍堵住：不派新轮、不写心跳，看门误报「车间停了」。目标是主循环一拍毫秒级。

## 做法

核心调插件一律经 `Engine.call`。守护进程（`workshop run`）给引擎一个 `Jobs`（`core/jobs.py`）：

- 一次插件调用就是一个**作业**，目录在 `<状态目录>/jobs/<编号>`，编号由端口、插件、方法和调用身份算出。
- 一拍里第一次碰到这次调用：写 `spec.json`，先锁好 `lock`，写 `pid=-1` 表示等待创建进程，再交给预先启动的单线程队列，立刻抛 `Pending`。启动线程用 `Popen(start_new_session=True, pass_fds=(lock,))` 起 `workshop job <目录>`，只把本作业的锁交给独立进程，原子写入真正的 pid。一拍最多登记 4 个新作业，其余下一拍再登记。线程仅创建进程，插件仍在独立进程里执行。
- 之后每拍回到同一处：有 `result.json` 就拿结果往下走；锁还被持有就是还在跑，再抛 `Pending`；锁空了又没结果，说明进程没写结果就退出了，按 `Retryable` 退避重试，不当成功。
- `Pending` 继承 `BaseException`，不被各处 `except Exception` 当成插件故障；核心在每件活、每一轮、每张卡、每个来源这一层接住它，跳过这一件，别的照常推进。
- 启动阶段也持有锁：其他引擎对象不会重复入队；启动者已退出且未写结果时按 `Retryable` 处理。创建进程失败写可重试错误；排队或创建期间超时，先记取消，启动线程跳过或在进程创建返回后结束它，不向占位 pid 发信号。
- 守护进程重启（含自更新后 launchd 拉起）：作业在独立会话里照跑，新进程照目录认回，不重跑，结果不丢。
- 作业超过 2 小时还没结果就整组结束，按 `Retryable` 处理；检查命令本身的超时仍由流程照规则 `check_timeout` 记 `exit_code=124`、`timed_out=true`，这件活检查没过。
- 结果复用：默认一直可用（一天没人取才清掉）；轮询、可用性这类会变的查询有新鲜期（来源和通道轮询 20 秒、执行者存活 30 秒、可用性和挑选 60 秒），对账取一次就清；出错的结果取一次就清，下次重跑。
- 完成钩子每次回查是一次新调用（回查次数进身份），不会认回上一次「还没好」的结果。
- 收尾后的工作目录收回：`Flow.hold_workdir` 和 `Executor.release` 也经作业执行；这一件在等时继续处理其他活。身份包含活 id、收尾轮次（`pending_episode`）、工作目录和延期时间（`release_at`）：同一次收回跨拍、跨重启认回；延期一小时再查、返工后再次收尾，都重新调用。`Release` 按值类型编码和还原，保留收回或留着的结果。
- 收回作业已启动时收到返工，先结算该作业再开新一轮，避免新一轮刚用上目录就被旧作业收回；只有查询作业在跑时不阻挡返工。
- 通道发卡：卡已标「发送中」而发送作业还在跑或已出结果时，直接认发送作业，不另去对账，免得把自己的发送算成不确定。
- 守护进程保留子进程对象，每拍用 `Popen.poll()`（内部 `waitpid(WNOHANG)`）收掉退出的作业进程（不等），定期清掉一天没人取的结果。
- 心跳 `heartbeat.json` 每拍写 `tick_ms`。100ms 是线上指标，单元测试只检查主循环不调用外部代码。独立看门每分钟读心跳，连续三次观测到不同的心跳且 `tick_ms > 100` 时，沿现有故障通道通知一次；`<=100`、无效数值或过期心跳中断计数。`watch.json` 持久保存最后观测、次数和序列起点，重启不重复计数或通知，恢复清故障。观测间隔超过 90 秒重新累计；这是连续三次看门观测，不是连续三拍（心跳每两秒覆盖一次）。
- `workshop status` 里，活在等流程的作业（核对证据、完成钩子、准备派活说明）时，状态一栏显示「等检查」。
- 一拍间隔从 20 秒改成 2 秒：一拍很便宜，而一件事要几次调用才走完（停执行者、核对证据、完成钩子），每次至少隔一拍。来源轮询仍约 20 秒一次（新鲜期管着）。
- `run --once` 和其他命令不带作业，插件调用就地进行（手工排查、测试）。

插件不用改：它们本来就把状态放在文件里，每次调用新起一个进程也一样。参数和结果按核心的值类型编码成 JSON；`classify` 要的只读查找在作业进程里自己开状态库。

`scripts/check.sh` 仍用八个 pytest worker，不增加或升级依赖。

## 测试分层

主循环结构测试以 `ManualJobs` 代替作业启动：真实 `Jobs.call` 仍登记和读取文件，启动替身只写说明、持锁，不创建进程也不自己写结果。引擎装入的插件方法一旦被调用就记录并报错；每拍后断言记录为空，防止异常被核心捕获后测试误过。测试在两拍之间显式写回结果，验证「等检查」、其他活派出和下一拍推进。

独立进程、重启认回、超时、退出无结果仍走真实 `Jobs` 和命令行入口；检查用信号阻塞，重启中的检查用文件门，作业超时推进注入的时钟并确认 SIGKILL。状态循环只查条件和总期限，不用固定睡眠。`test_jobs.py` 不再有长等待，也不再需要 `JobScheduling` 固定 worker；`pytest -n 8` 使用默认调度。

### 按文件、函数核对源码

路径均相对 `src/workshop/`。上表第一列的函数都属于 `core/engine.py:Engine`；下表给出实际执行外部命令或请求的位置。核对命令为 `rg -n 'subprocess|urlopen' src/workshop`（等价于验收中的 `grep -rn 'subprocess\|urlopen' src/workshop`）。导入、异常类型和 `subprocess.STDOUT` 不是额外调用，归入所在函数；同一函数的不同命令列在同一行。

## 创建进程的结构回归

主干 ws#44 已将启动线程的创建入口从 `os.posix_spawnp` 改为 `Popen(start_new_session=True, pass_fds=(lock,))`，只交本作业锁，保留子进程对象并用 `poll()` 非阻塞回收。本 PR 保留这个修复；ws#71 的 EPERM 修复也从主干合入，不在本单重写。

`test_slow_process_creation_does_not_hold_tick` 记录真实 Popen 调用线程，断言都在主线程以外。`test_native_process_creation_does_not_hold_tick` 保留主干新增用例名，删除 FIFO 的 250ms 人为延迟及所有墙钟断言，改为禁止旧 `os.posix_spawnp` 入口、核对 Popen 在后台线程且使用独立会话和单个锁文件描述，并确认别的活真正启动。进程启动期间认回、取消、早完成结果和启动失败仍走真实进程测试。

## 主循环历史扫描（#167）

一拍按需要读活：推进只读未结束或仍有返工、程序结算、完成钩子、待批准推进的活；来源只读挂着程序阶段的活；收目录只读已完成且目录尚未收回的活。结束后的工单仍按修订同步一次，覆盖索引先找未同步项，之后不再反复读取它的正文。排队占位和下一次唤醒也走这些查询。已完成操作与已触发定时记录通过部分索引排除。

数据和说明格式不变，只新增索引。真实状态库只读备份（2026-11-16，161 件活、1141 轮、229155 条事实）上，基线连续五拍 1656–1668 ms，改后 56–62 ms；首次打开并创建索引 224.051 ms，引擎初始化 0.498 ms。profiling 的基线一拍为 1686 ms，JSON 解码累计 1373 ms；最大的几份资料属于已放弃的活，却被每拍反复读取；另有 12353 条操作和 11589 条定时记录被全量扫描。优化后 profiling 五拍均值约 63 ms，其中推进约 52 ms。事实和活的正文没有迁移；用基线代码重新打开优化后的副本，161 件活逐字一致，1141 轮说明均可读。此为存储读取的旧版兼容验证，不冒充真实发版回退实测。

复测：`uv run python scripts/measure_tick_copy.py --source <只读备份路径> --output <新目录> --ticks 5`。输出区分存储打开（含首次创建索引）、引擎初始化与逐拍耗时；外部作业只登记不执行，不能代替生产验收。测试以实际读取字节量、SQLite VM 步数和索引查询计划锁定回退，不使用 sleep 或墙钟通过阈值；另覆盖结束后工单同步和返工继续执行。

真实发版时，在预期重启前启动 `uv run python scripts/measure_release_gap.py --output <新JSONL路径>`。默认只读采样 30 秒，每 50 ms 读一次文件，不启动 pgrep，不触发发版。心跳的 `process` 记录 PID、启动时加载的版本、首次心跳及覆盖前的末次心跳；后续心跳持续携带这两个端点，避免首拍很快而被采样遗漏。端点身份缺失、未覆盖换代或空窗超过 1 秒均不能通过；首次从没有进程标记的旧版本升级，需要另行取得旧进程身份，或在下一次真实发版完整验收。另按 issue 要求采集生产 60 秒心跳和看门自动恢复证据，未取得时不得用副本数据宣布通过。

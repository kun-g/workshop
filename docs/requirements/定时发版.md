# 定时发版需求

这份文档管定时发版这个流程插件：车间自己和 grant-console 合并了的改动，怎么定时上线。阶段和关口本身见 [核心.md](核心.md)；车间自己的活合并就算交付，见 [issue交付.md](issue交付.md) 的 R3；怎么做见设计文档（还没写）；用词以 [GLOSSARY.md](../../GLOSSARY.md) 为准。每条都经 Kun 认过，改之前先问他。

## 要的结果

车间自己和 grant-console 的合并每小时上线一次；车间自己新版本起不来，自动退回上一版。grant-console 每批保留一次指定应用和版本的同步授权，失败不自动回滚。

不归这里：

- 其他交付对象怎么上线，归 issue 交付和各自的规则。
- 车间停了、卡住怎么让你知道，归核心的 R23。
- 合并前的检查和验收，归 issue 交付。

## 要求

R1–R5 只管车间自己；grant-console 按 R6 执行。

### 什么算定时

**R1 每个整点，守护进程在跑的版本落后远端 main，就开一件发版的活；没有就丢弃这次，不开活。在跑的版本由守护进程启动时记下，不看主检出。**
为什么：Kun 11-14 定「每个小时」。现在每合并一次就快进主检出、重启守护进程（规则里的 `release: self`）。
比在跑的版本：主检出会被别的程序提前快进（Orca 建工作区时快进本地 main），比主检出时整点就以为已上线而跳过（#126）。Kun 11-16 定「对比正在运行的版本跟当前最新的版本」，和 R6 比实际上线版本一致。

### 什么算上线

**R2 上线前在要上线的提交上跑 `scripts/check.sh`；不过就不上线，通知你一次。**

**R3 检查过了，快进主检出、重启守护进程，心跳恢复才算交付。全程由程序做，不起 agent。**

**R4 发版不等手上的活跑完；正在跑的执行者和作业，重启后认回来接着跑。**
为什么：现在合并后马上重启也不等，靠的是重启后认回。

### 什么算退回上一版

**R5 发版后 3 分钟内心跳没恢复，看门程序把主检出退回发版前在跑的版本、重启守护进程，通知你一次；同一个提交不再重发，有更新的合并时，下个整点自动再试。**
为什么：新代码坏了时守护进程自己可能起不来，退回得由它以外的进程做；看门程序每 60 秒由 launchd 单独起一次。Kun 11-14：「走回退」。
再试方式：Kun 11-14 在实施计划第 5.1 条选「有更新的合并就自动再试」，见 issue #78；不再发卡等他点继续。

### grant-console 的整点批次

**R6 grant-console 也按整点定时发版：每个整点，比较实际上线版本的源提交与 main 的累计改动。全落在规则配置的无需上线路径（`docs/`、`**/tests/`、`*.md`）时不开批次；有服务变化才固定本批提交，按手册打 tag、等 CI、推 production。每批只申请一次 `argocd/sync_app` 代执行，绑定指定应用和完整版本，Kun 批了才同步，rollout 完成才算交付。第一屏写本批服务变化和全部单据标题，tag、提交、digest、批次等编号收在折叠区。只有显式创建 Secret 等代执行确实不能覆盖的需求，才能单独说明原因申请集群权限；执行失败、超时、结果不明都不能退回更宽权限。上一申请未决时不发新卡；确认拒绝或过期，这个提交不再重发，有更新合并时下个整点再试；同步或 rollout 失败记卡住，不自动回滚。**
为什么：Kun 11-15「也改成定时发，也一样是每个小时一次」。返工时项目经理说明文档/测试免发版、卡片人话在前技术编号折叠、默认精确代执行三项后，Kun 在 2026-11-15 08:25:42Z 回「我批了，你继续」（issue #122 评论 6891675923；会话 6c36ee03-f390-41b5-9ba1-a7eb82c6fd16）。卡片由负责 agent 先按授权中心审批卡 R1–R6 核对，Kun 只做真实授权批准或拒绝，不另问「是否读得懂」。

## 约束

核心的 C1 到 C4 都适用，这里没有另加的。

## 衡量

| 指标 | 量的是 | 目标 | 现在 |
|---|---|---|---|
| 合并到上线的时间 | 定时（R1） | ≤ 1 小时加一次检查 | 合并后马上上线 |
| 退回上一版的次数 | 合并前的检查漏了什么（R5）；同次回退的重复看门运行不重复计数 | 先只记，逐周看 | 本次成功回退写 rolled_back_at；历史周汇总未实现 |

## 按默认定

追问时列过、Kun 没反对的，已写进正文：

- R1 没有新合并就丢弃；R3 全程不起 agent；R4 不等手上的活（11-14）。
- R5 同一个提交不重发，有更新的合并时下个整点自动再试（11-14，Kun 在实施计划中确认，issue #78）。

# 记忆需求

这份文档管车间自己的记忆：跨活、跨会话要留下的东西存在哪、每轮开头带哪些、做梦怎么加、被纠正的条目怎么不再回来。阶段和关口本身见 [核心.md](核心.md)；怎么做见设计文档（还没写）；用词以 [GLOSSARY.md](../../GLOSSARY.md) 为准。每条都经 Kun 认过，改之前先问他。

## 要的结果

会话压缩或换会话以后，该留的还在；每轮开头只带当前作用域该带的；用户纠正过的说法不会换个写法复活。依据记忆 R36，前置 #311（R34 的调度）和 #312（已告知记忆依赖真实 outbox 状态流转）。

不归这里：

- 每类活自己的记录和阶段，归它的插件；记忆不替代事实表。
- 授权中心、接线台的边界，归它们自己。

## 要求

**R36 记忆独立持久，能做「做梦」，且不复活被纠正的条目。**

判据：

一、记忆在事实表之外单独存（`memory.db`），跨活、跨会话可读；每条带来源事实 id（`source_fact_seqs`）和生成批次，能溯源。不写主事实表，事实表仍是事件真相来源。`memory.db` 是唯一不能只靠事实表重放的派生层（纠正行和做梦结果），所以整体备份、整体恢复。

二、四类分开：用户指示（每轮开头加载）、用户笔记（开头只加载索引，用到再读）、已经告诉过用户的（避免重复说）、任务进度（一件活一条进度，和其余记忆在同一份存储里）。开头加载只取当前作用域（用户指示、未结案的进度、近期告知），并有条数和字符预算上限，超限按优先级截断：用户指示 > 未结案进度 > 近期告知，用户指示不能被挤出；笔记只加载索引（id/摘要），正文按需读，只有 `workshop memory show <id>` 才返回正文；不无界全量加载。已结案的进度不进开头加载。

三、只存查不回来的东西；能再查到的只存指针。

四、做梦是独立过程，手动触发 + 每周一次；只写派生层，不改只追加的事实表。做梦带持久游标：没有新事实时重跑不产生重复条目；中途失败重跑不丢不重。每周做梦和每周备份都登记成核心 R34 的周期任务（任务号 `memory-dream`、`memory-backup`），到点开一件活，入口是那件活的流程步骤，不另起定时器。每周备份的路径必须在状态目录之外，资料地图（data-map）登记的位置与之一致；备份可整体恢复，恢复前检查完整性，重启守护进程后记忆库可读。

五、纠正记录针对（条目、来源事实集合），不把来源事实全局标脏。用户删除或纠正一条记忆时，在 `memory.db` 追加一条带权重的负向纠正行（不是主事实表），记下纠正时的来源水位、原条目的来源事实和一个等价判定用的说法（`phrase`）；原条目立即下线，下一轮不再加载，备份后恢复仍不出现。做梦候选同时满足两条才拒绝：候选引用的来源事实全部不晚于纠正水位（没有引入任何晚于纠正的新事实），且等价判定认为它和被纠正条目是同一个说法。同一事实支撑的其他不同记忆照常保留；候选引用了晚于纠正水位的来源事实时放行。等价判定用模型，超时或返回非法格式时按拒绝处理（fail-closed）；测试里 mock。轮内写入用 `workshop memory add --token <round>`，令牌无效、不属于该轮、或该轮结束后复用时拒绝；必须带真实存在的来源事实。

六、会话压缩或换会话后记忆仍在；每轮开头加载固定部分。

为什么：压缩会丢细节，要留的必须进记忆；用户纠正的条目再换个说法回来，等于纠正没发生。代价：派生层和事实表可能不一致，所以每条记忆能溯源；纠正行和做梦结果不能从事实表重放，`memory.db` 单独备份并整体恢复。每周做梦和每周备份共用 R34 已有的调度，而不是再写一个定时器，否则就有两套到点判断。

## 约束

核心的 C1 到 C4 都适用，这里没有另加的。记忆做成新插件 `src/workshop/plugins/memory/`，不直接 import 介入点等其他插件；送达状态经核心定义的 outbox 只读端口读取，以 sqlite `mode=ro` 只读打开介入点库。核心只加端口接口和派活说明里「记忆」一节的组装，不改主循环、阶段和关口。不新增依赖，存储用标准库 `sqlite3`。`scripts/check.sh` 里的测试不连真实模型，做梦生成器用 mock。

## 衡量

| 指标 | 量的是 | 目标 | 现在 |
|---|---|---|---|
| 每轮开头带上的记忆条数、字符数 | 判断更少（缓存和注意力） | 不超预算，用户指示不被挤出 | 刚建 |
| 被纠正的条目换个说法复活的次数 | R36 五 | 0 | 还没开始量 |
| 做梦重跑写出的重复条目数 | R36 四 | 0 | 刚建 |

## 按默认定

追问时列过、Kun 没反对的，已写进正文：

- 预算默认条数和字符数由规则 `memory.budgets` 给出，超限按用户指示 > 未结案进度 > 近期告知截断。
- 每周做梦、每周备份共用 R34 的到点扫描，任务号固定为 `memory-dream`、`memory-backup`。

# 项目经理

项目经理是在车间旁边给整个执行兜底的 agent 会话：盯着活往下走，用现有命令疏通卡住的活，把看到的问题记下来、报给 Kun。车间的目标是自己运转；现阶段还做不到，需要项目经理在旁盯着。

项目经理只记录和汇报问题；怎么解决，由协调对话去想根因和改法、问 Kun、开单（见 `docs/协调对话.md`）。理想状态下项目经理没事可做。

## 规矩

除 `AGENTS.md`「规矩」以外，项目经理还守这几条。细节和来历见 `docs/knowledge/` 下同编号的文件。

- P2 车间要在适当负载下持续运转：指标按供给、流动、负载三段看，按小时出数。
- E1 发卡前用线上渲染代码看第一屏：看不懂、有编号、权限比事宽，就先拦下。
- E2 后台等待写预期时间，到点没变化也叫醒；工具是 `scripts/pm/watch.py --by`。
- E3 网络排障先查实际路径：context、客户端、代理、出口 IP。
- E6 项目经理不开单：问题和证据记进问题记录，开不开由协调对话问 Kun。
- E7 有 PR 卡着时，新单不打开工标签，先解在途 PR 的卡点。
- E12 Orca worker 的 PR 合并后，同一步关掉它的终端。

## 开场

1. 读 `contexts/projects/workshop/pm.md` 的「现在在哪」、`contexts/projects/workshop/问题记录.md`，再读上一任项目经理的交接。
2. `uv run workshop status`：看在跑的轮次、等回答的问卡和卡住清单。
3. 和别的项目经理分清各自管哪几件活，写进 pm.md。不动别人管的活。

## 盯

- 后台盯梢交给脚本，不靠模型轮询。脚本有变化才叫醒项目经理；不主动给 Kun 发进度，见 `notices: hold`。
- 发现守护进程跑的是旧代码，或者交付对象被标坏，先查清原因再恢复。不要等在跑的轮次结束：轮次是独立进程，重启守护进程会把它们接回来。

## 疏通

只用下面这些命令，加上「还只能手工的」表里列出的做法，让活接着走。不改代码，不改规则，不改需求。

现有命令：

| 情况 | 命令 |
|---|---|
| 一件活每一轮发生了什么 | `workshop why <活>` |
| 停下的活要返工，Kun 有原话 | `workshop recover <活> --mode rework --reason … --quote …` |
| 等待次数用完后还要继续回查 | `workshop recover <活> --mode wait --reason …` |
| 重验次数用完，追加一次验收 | `workshop recover <活> --mode verify --reason … [--ref main]` |
| Kun 在会话里回答了问卡 | `workshop answer <Q 号> <选项> --quote … --session …` |
| Kun 在会话里说了「放」 | `workshop release <活> --quote … --session …` |
| 不做了（Kun 说的） | `workshop abandon <活> --reason …` |
| 误建、还没跑过的活 | `workshop drop <活>` |
| 交付对象被标坏（例如 App 令牌一时签不出） | 先手试签发，确认通了再 `workshop resume <交付对象> --select none --seen none` |
| 车间自己急着上线 | `workshop release-now` |
| 用 App 身份调 gh（E10） | agent 会话里直接用 `gh` 和 git：身份包装器只用 App（workspace `runtime/tools/agent_github_identity` 严格模式），grant-console 也一样；要以 Kun 的名义做的走 `gh-human`。发完核对 `.user.login` 是 `lambdatheory-agent[bot]` |

车间还没有命令的情况（解卡、撤问、加资料、已完成的活返工、核对后收集群批次、自动恢复），用 `scripts/pm/` 里的工具，用法和各自缺的机制见那里的 README。每用一次，记进问题记录。

已知某个来源接下来只会发无用卡时，现在只能整个交付对象 `pause`，会连带停掉别的活。停之前先记进问题记录，再问 Kun。

## 记录和汇报问题

- 看到的问题、做过的手工干预，都追加到 `contexts/projects/workshop/问题记录.md`，一行一条：时间、现象、证据、影响到的活、状态。
- 只写看到了什么，不写改法，不开单。设想的问题（「可能会」「大批次时也许」）不记。
- Kun 问起时，先说等他的事，再说新记的问题。

## 找 Kun

- 只为要他授权或回答的事找他，例如发版卡、车间发出的问卡。带推荐和理由，一张卡只问一件事。
- Kun 只批或拒，不让他回话确认。结果由项目经理自己去查。
- 卡发给 Kun 之前先自查（E1），工具是 `scripts/pm/render_gc_card.py`。不过关就先拦下，并记进问题记录。

## 不能做

- 不写改法，不改代码、规则和需求文档。
- 不可逆、对外、花钱的事，先问 Kun。
- 要权限走授权中心（`request_grant.py`），不换身份、不绕过。
- 令牌不打印。

## 交接

停下时写交接，内容包括：会话号、worktree、续接命令、在途的活和它们在等什么、这次新记的问题。交接写进 pm.md。

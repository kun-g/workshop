# 实测：Orca 新终端里 `claude --resume` 接回原会话

日期 2026-11-13，Claude Code v2.1.323，Orca CLI（`/Applications/Orca.app/Contents/Resources/bin/orca`）。为实施计划里「等你时会话退出，你答了接回原会话」的做法先试一次。

## 结论

能接回。车间写代码执行者照这个做：

1. 第一轮起会话时自己定会话 ID：`claude --session-id <uuid> …`。会话里的 `CLAUDE_CODE_SESSION_ID` 就是这个 uuid，车间不用事后去找。
2. 一轮结束，车间用 `orca terminal close --terminal <handle>` 关掉终端；claude 进程随之退出，会话记录（`~/.claude/projects/<cwd 编码>/<uuid>.jsonl`）留在原处。
3. 下一轮新开一个 Orca 终端：`claude --resume <uuid> --model … --permission-mode bypassPermissions "<新说明>"`。会话 ID 不变，记录追加在同一个文件里，新终端里能看到前几轮的对话，新说明直接作为这一轮的第一条消息。

## 要注意的

- 交互式 claude 做完不会自己退出，终端停在输入框。一轮什么时候算完由车间决定（会话交回执后车间关终端），不能等进程退出。`orca terminal wait --for tui-idle` 可以当兜底信号，这次没试。
- 接回前要确认上一轮的终端已经关了。两个终端同时挂在同一个会话上没试，车间不应让它发生。
- 换目录也能接回：在 `/tmp` 里 `claude --resume <uuid> -p …` 照样答出暗号，记录仍追加在原文件里。车间仍应在原 worktree 里接回，代码和会话记录才对得上。

## 过程和原样输出

第一轮（haiku，省钱；接回的机制和模型无关）：

```
$ U=$(uuidgen | tr A-Z a-z)      # b80d735d-f6fc-4cfd-bf94-2b6ed7c06000
$ orca terminal create --worktree "path:$WT" --title "车间实测 接回会话 1" \
    --command "claude --session-id $U --model haiku --permission-mode bypassPermissions \"\$(cat p1.md)\"" --json
# p1.md：记住暗号「蓝鲸-4721」，把 $CLAUDE_CODE_SESSION_ID 写进 r1.txt，回复「记住了」
$ cat r1.txt
b80d735d-f6fc-4cfd-bf94-2b6ed7c06000
```

关终端：

```
$ orca terminal close --terminal term_17f30fa2-… --json
$ ps -p 71342 → pid gone；pgrep -f "session-id $U" → claude gone
$ wc -l ~/.claude/projects/-Users-kun-workspace-runtime-worktrees-workshop-workshop-build-lead/$U.jsonl
      67
```

第二轮，新终端接回：

```
$ orca terminal create --worktree "path:$WT" --title "车间实测 接回会话 2" \
    --command "claude --resume $U --model haiku --permission-mode bypassPermissions \"\$(cat p2.md)\"" --json

```
